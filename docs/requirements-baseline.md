# 需求基线

状态：设计基线 v0.2  
日期：2026-08-30  
目标平台：Nuvoton MA35D1-IoT，ARM64，Ubuntu 22.04

## 1. 产品目标

管理机是局放监测设备与上位系统之间的边缘网关，必须同时完成：

1. 从 485-1 以 Modbus RTU 主站方式采集一台地址为 1 的 PD1000。
2. 把一份一致的数据快照镜像到 485-4 Modbus RTU 从站和网口 1 Modbus/TCP 从站。
3. 把 5 个测量值发布为 IEC 61850 MMS 数据；谱图不进入 IEC 61850。
4. 提供带登录的本地 Web 管理、实时数据显示、配置、健康状态和日志查看。
5. 周期或事件触发保存测量值与谱图，并按保留期和磁盘水位自动清理。

## 2. 采集协议基线

### 2.1 串口与帧

- 接口：485-1，产品默认设备节点 `/dev/ttyS1`；后续按此接线，实机阶段只验证电气和收发是否正确。
- 协议：Modbus RTU，115200 / 8N1，从站地址 1，功能码 `0x04`。
- 一轮包含 31 笔顺序请求：
  - 第 1 笔：地址 10001，15 个输入寄存器。
  - 第 2–31 笔：从地址 10016 起，每笔 120 个输入寄存器，连续覆盖到 13615。
- 线上的 PDU 起始地址就是十进制 10001–13615；不得擅自减 1。源需求的首帧明确为 `01 04 27 11 00 0F EA BF`，31 个 CRC 已在设计阶段全部复算通过。必须再用抓包/伪终端和实机证明地址、数量与响应一致。
- 部分 SCADA 工具把“10001”当作显示编号并在线上发送 10000。UI/手册必须明确本项目使用线地址 10001（`0x2711`），验收同时包含“标准显示编号减一”客户端的失败提示，不能静默错位。
- 正常完整轮询从轮次开始到快照发布不得超过 6 秒。
- 每个正常响应的最后停止位到下一请求首字节之间保持至少 3.5 字符时间；115200/8N1 实现采用更保守的 1.75 ms 下限。用串口抓包/逻辑分析仪验证正常路径，而不只验证错误恢复路径。

### 2.2 数据解释

| 地址 | 字段 | 类型 | 单位/范围 |
|---|---|---|---|
| 10001 | 通道 1 放电信号均值 | int16 | dBm，-70…15 |
| 10002 | 通道 1 放电频次 | uint16 | 次/秒，0…65535 |
| 10003 | 通道 1 放电信号峰峰值 | int16 | dBm，-70…15 |
| 10004 | 通道 1 放电量峰值相位 | uint16 | °，0…360 |
| 10005 | 通道 1 背景噪声 | uint16 | mV，0…4096 |
| 10006–10015 | 预留 | 原始 uint16 | UI/IEC 不解释，但 Modbus 必须原样镜像 |
| 10016–13615 | 50 × 72 谱图点 | int16 | dBm，-70…15 |

谱图索引为 `index = cycle * 72 + phase_bin`，`cycle=0…49`，`phase_bin=0…71`，相位为 `phase_bin * 5°`。

特殊值：

- `0xFFBA`（-70 dBm）：无效数据段标记，图表应显示为空缺，不作为真实幅值聚合。
- `0xFFBC`（-68 dBm）：设备未刷新占位；整幅均为此值时，快照状态为 `not_refreshed`。
- 谱图的 `0xFFBA` 虽然数值上等于量程下限 -70，但协议已把该原始码保留为无效标记；实现必须保留逐点 validity mask，不能只存 `int16` 后再猜。
- 10001、10003、10004、10005 超出表中范围时，对应测量点语义质量为 invalid；10002 的完整 uint16 范围均合法。原始寄存器仍进入透明 Modbus 镜像，但无效点不得作为正常值进入 Web/IEC 或事件规则。

### 2.3 一致性与失败语义

- 只有 31 笔全部通过长度、从站号、功能码和 CRC 校验，才发布新的完整快照。
- 单笔失败按需求最多重试 3 次、间隔 100 ms，但重试是 6 秒总预算内的 best-effort；达到截止时间立即中止本轮，不可为了凑满重试次数延长。首次尝试优先于重试，不能让前面坏块耗尽后续块的首次机会。
- Modbus RTU 响应不携带起始地址，因此同为 120 寄存器的迟到响应无法与下一块可靠区分。只有已经完整收齐、边界明确的异常帧或 CRC 错帧允许在同一地址安全重试；超时、短帧、长度/边界错误立即放弃整轮，不发送下一地址或即时重试。
- 放弃整轮后持续排空串口，必须得到完整 6 秒无任何接收字节的隔离静默窗才可从地址 10001 开始新一轮；任何迟到字节都重新计时。实机门必须证明 PD1000 不会在 6 秒隔离窗之后发送旧响应，否则本协议在无事务号的 RTU 上不能安全发布数据。
- 每次阻塞读的超时都不得大于当前轮剩余时间；任何错误后的下一次发送仍须满足 1.75 ms 帧间静默。隔离期间不得把收到的字节解释为新请求响应。
- 部分成功的轮次不覆盖已发布快照，避免 Modbus/IEC/Web 看到混合新旧数据。
- 若已有完整快照，传输失败时继续提供最后完整值，并把对外新鲜度标记为 `stale`；该快照原有的 `good/degraded/not_refreshed` 载荷状态和逐点质量保持不变。若启动后从未成功，对外可用性为 `invalid`，Modbus 返回设备故障异常，IEC 质量为无效，Web 不显示伪造的 0。
- 状态分成正交的两轴：完整载荷状态 `good/degraded/not_refreshed`，以及对外可用性 `fresh/stale/invalid`。整幅谱图全为 `0xFFBC` 时载荷状态优先为 `not_refreshed`，即使另有测量点 invalid 也保留在逐点质量中；非全域占位时，任一点 invalid 则载荷状态为 `degraded`。
- 每个完整快照包含单调递增序号、采集开始/结束时间、轮询耗时、载荷状态、5 个解析值及质量、3615 个原始寄存器、3600 点谱图及 validity mask；独立的最新采集尝试状态记录成功/失败、错误和时间，并与快照组合成对外视图。

## 3. 转发需求

### 3.1 Modbus RTU 从站

- 接口：485-4，产品默认设备节点 `/dev/ttyS4`；后续按此接线。
- 参数：115200 / 8N1；从站地址网页可配，默认 1。
- 只实现输入寄存器读取 `0x04`；范围 10001–13615，共 3615 个寄存器。
- 非法功能码、非法地址和无可用快照必须返回标准 Modbus 异常，不可静默或崩溃。

### 3.2 Modbus/TCP 从站

- 绑定网口 1（当前为 `eth0`）的地址，默认 TCP 502，端口可配。
- Unit ID 独立配置、默认 1，和 RTU 从站地址显示在同一通信设置区。只接受匹配配置值的 1–247；不匹配时返回 Modbus/TCP 网关目标设备未响应异常 `0x0B`，不得静默映射到其他单元。
- 暴露与 RTU 相同的 `0x04` 地址空间和快照。
- 支持多个连接；慢客户端不得阻塞采集和其他协议服务。

### 3.3 IEC 61850 MMS 服务

- 默认 TCP 102，可配置但 UI 必须提示 102 是标准 MMS 端口。
- 只发布 10001–10005 的 5 个测量值，同时发布时间戳与质量。
- 管理机是 IEC 61850 服务端。需求书中的“客户端断开后自动重连”解释为：客户端断开不影响采集，服务端持续监听并允许客户端重新连接。
- 采用 IEC 61850-7-4 的通用局放模型：`LLN0 + LPHD1 + SPDC1 + GGIO1`。`SPDC1.UhfPaDsch` 发布峰值，`SPDC1.PaDschAlm` 发布事件告警；`GGIO1` 用标准编号数据对象发布全部 5 个原始测量语义。
- 第一版支持模型浏览、读值，以及一个包含 5 个值和告警的 URCB（数据变化触发、60 秒完整性周期）。不实现 BRCB、控制、写入、GOOSE、SV、MMS 文件服务或动态数据集。

## 4. Web 与用户需求

### 4.1 登录与权限

- 单一 `admin` 管理员账号即可；所有配置、日志下载和维护操作都要求登录。
- 安装时写入一次性默认初始密码 `admin`，只写入 root 可读文件；管理员可在登录后主动修改。仓库、日志和 API 响应不得包含明文密码。
- 密码使用带随机盐的 PBKDF2-HMAC-SHA256 或经确认的 Argon2 实现；会话为随机服务端会话，Cookie 使用 `HttpOnly`、`SameSite=Strict`，HTTPS 模式下增加 `Secure`。
- 登录失败按源 IP 限速；除登录创建会话外的所有修改接口使用 CSRF 令牌，登录请求校验同源 `Origin`；重启、网络变更和恢复默认值要求再次输入当前密码。
- 产品模式默认使用 HTTPS；安装时生成设备自签名证书用于首次接入，并允许管理员原子替换为用户提供的服务端证书/私钥。HTTP 只能通过本机恢复配置显式启用，且页面持续显示明文链路警告；HTTP 下密码不能保密。

### 4.2 页面

1. 登录页：账号、密码、错误提示、首次登录改密。
2. 总览页：5 个测量卡、快照质量、最后成功时间、轮询耗时、PRPD、PRPS、各协议健康状态。
3. 通信设置：采集从站号/超时/重试；RTU 从站号；Modbus/TCP、IEC 61850、Web 端口；IED 名称。
4. 网络设置：eth0/eth1 的 DHCP/静态模式、IP、掩码、网关、DNS；显示物理链路状态。
5. 存储设置：周期保存间隔、触发规则、保留天数、磁盘低水位。
6. 日志与健康：最近事件、过滤、下载、组件状态、版本和资源占用。
7. 安全与维护：修改密码、导出脱敏配置、重启服务/设备。

旧 `/data` 页面的卡片式导航、蓝色主色、清晰表单和日志页面可作为视觉参考；旧页面没有登录且危险操作使用 GET，不可复用其权限和接口设计。

### 4.3 实时数据

- 新快照发布后通过 WebSocket 推送，正常约每 6 秒一次；断线后自动重连，HTTP 拉取为降级路径。
- PRPD：50 × 72 热力图，x 为相位，y 为周期，颜色为 dBm；无效/占位点单独处理。
- PRPS：以相位、周期/时间和幅值呈现散点或栅格，不在服务端生成大图片。
- 图表库和字体必须随发布包离线提供，不依赖公网 CDN。

## 5. 配置、日志与数据存储

- root 只读的出厂默认和 schema 放在 `/etc/uhf-gateway/`；可由 Web 修改的运行配置与账号哈希分别放在 `/var/lib/uhf-gateway/config.json` 和 `auth.json`，由服务用户所有、目录 0700、文件 0600。
- 每次修改先做完整验证，再写临时文件、`fsync`、原子替换；保留一个最后成功版本。
- 普通端口/业务参数可热加载；串口设备、IED 名称和部分 IEC 模型变更允许安全重启服务。
- 网络配置必须由独立 root 事务服务试应用：先保留旧地址/路由并把新地址作为辅助地址加入（make-before-break），开启持久化 60 秒回滚计时；新地址确认成功后才切换持久配置和移除旧地址。事务服务或整机重启后也必须继续回滚未确认事务。只允许一个默认网关，且不得停止/重启 frpc 或 4G。
- 静态候选包含接口、IP/prefix、可选网关和 DNS；DHCP 候选包含接口、主机名和 15 秒取租超时。DHCP stage 使用隔离客户端取得租约，只把地址和低优先级候选路由加入内核，不覆盖旧配置/默认路由；页面显示实际租约地址，confirm 后才原子写入板卡 DHCP 持久配置，rollback 停止候选客户端并删除租约地址/路由。
- 60 秒在同一开机周期内以 `CLOCK_BOOTTIME` 为唯一权威，不受 RTC/NTP 跳变影响；事务同时记录 Linux boot ID。特权服务重启且 boot ID 未变时按原 boottime 截止继续，boot ID 改变、事务损坏或时间无法判定时在启动网络服务前立即回滚，不把等待期延长到新开机周期。
- 应用日志进入 syslog/rsyslog 的独立设施和文件，由 logrotate 按天或 5 MiB 轮转，默认保留 7 天并压缩。不得在每条日志写入时扫描或删除文件。
- Web 只显示经过长度限制和转义的最近日志，不允许读取任意路径。
- 谱图存储使用带版本、时间戳、质量、3615 个寄存器和 CRC 的紧凑二进制帧；需要 CSV 时按需导出，避免持续写大 CSV。
- V1 有两类独立事件：强放电事件在 fresh 且 valid 的 10003 峰值 `peak >= -45 dBm` 时触发，降到 `-50 dBm` 以下重新布防；突变事件在当前峰值与上一次有效峰值满足 `abs(current_peak - previous_valid_peak) >= 10 dB` 时触发。两类条件同一轮同时成立时只建立一个事件包，但记录两个 reason。
- 事件包保存触发前 2 个完整 generation、触发 generation、触发后 3 个新完整 generation，共最多 6 帧；若前帧不足则保存已有帧，若触发后 30 秒仍不足 3 帧则以 partial 标记结束。stale、invalid、not_refreshed 和峰值 invalid 不参与触发，也不替换上一次有效峰值；启动后的第一份 fresh/valid 峰值只建立比较基线。
- 从首次触发起 60 秒内的同类事件合并到同一事件包，只累计 `merged_count`、最大峰值和最大差值，不重复附加超过上述 6 帧，也不延长 60 秒窗口。不同类型分别合并；若同一事件包同时含两类 reason，则分别维护计数。
- 默认每 300 秒保存；事件帧另存。默认保留 1 天，清理任务每小时运行。低水位为 `max(storage.min_free_bytes（默认 512 MiB）, 文件系统容量的 10%)`，任一条件触发后先删过期帧，再按时间删除最旧的已关闭帧，直到达到 `max(低水位+256 MiB, 15%)`。
- 清理永不删除正在写入的临时文件、最新一份已关闭帧、配置/账号/TLS 文件、发布包或日志；日志由 logrotate 独立管理。删除失败时记录受节流的 critical 事件并暂停新数据帧写入（计数丢弃），但采集和协议服务继续；下次小时任务及磁盘状态变化时重试。

## 6. 非功能验收

| 编号 | 验收条件 |

| NFR-01 | 连续 10,000 个正常轮次，完整轮询 P99 ≤ 2 秒；任何阻塞调用和轮次状态在 6 秒截止时结束，之后只能进入独立、可观测且不阻塞对外服务的链路隔离状态 |

| NFR-11 | HTTP/WS/IEC/存储/日志队列都有连接数与字节硬上限；过载按规定合并/丢弃并告警，不得因无 Swap 导致 OOM |

## 7. 已确认决策与实机验收项

### DECISION-IEC-MODEL：通用 IEC 61850 模型

当前没有客户专用 ICD/CID，也没有特殊报告要求。V1 固定使用 `LLN0 + LPHD1 + SPDC1 + GGIO1`、一个静态数据集和一个 URCB；发布仓库包含可复现生成的 ICD。若以后客户提供模型，再作为兼容性变更处理，不阻塞当前实现。

### DECISION-IEC-LICENSE：GPLv3 兼容开源

产品及其对应源码允许公开发布，项目仓库为 public。项目采用 GPLv3 兼容许可证，并使用 libIEC61850 的 GPLv3 版本；发布二进制时同步提供对应版本源码、构建脚本、许可证和第三方声明。WP0 复核准确 SPDX 标识后提交 `LICENSE`，无需购买商业许可证。

### DECISION-TRIGGER：V1 两类事件保存

V1 同时实现强放电和突变事件。强放电使用 `peak >= -45 dBm`、`peak < -50 dBm` 重新布防；突变使用当前峰值与上一次有效峰值之差的绝对值 `>= 10 dB`。每个事件保存前 2、当前、后 3 帧，同类事件 60 秒内合并；无效、过期和全占位数据不触发，也不更新上一次有效峰值。

### ACCEPTANCE-HARDWARE：接线后实测

当前没有任何 485 接线。实现按 485-1 → `/dev/ttyS1`、485-4 → `/dev/ttyS4` 开发；接线完成后验证收发方向、终端电阻、地址、115200 稳定性和 PD1000 最迟响应，不再把设备节点映射作为待设计问题。
