## 正式程序入口与当前边界

当前正式入口仍是 `src/main.cpp` 启动的 `uhf-gatewayd`。使用 `--v3 --v3-pd-device PATH --v3-current-device PATH --v3-temperature-device PATH` 时，它创建三个真实串口、`v3::AcquisitionScheduler`、v3 Modbus/TCP/RTU 分支、候选 IEC 三合一模型、v3 Web 快照和 `data/v3` 历史存储；不传 `--v3` 仍保持旧 PD1000 兼容路径。激活门禁尚未接入，因此不能把该入口写成整机三合一交付。

下一增量应补并发 PTY 守护进程端到端测试、网页配置和存储空间/保留期故障测试，再完成最终 IEC 点表/报告互操作、12 点阈值配置和激活总门禁。生产所需电流/温度编码倍率、谱点单位、无效/过期对外值和最终 IEC 点表仍需产品输入，代码不得用测试值伪装配置完成。

## 已知暂定策略

- `CollectorOptions::max_retries` 表示首次尝试之外的重试次数，当前默认 3；需求“重试 3 次”尚未明确总尝试次数。
- 局放分段间隔默认 3 秒；PTY 测试把它设为 0。该设置会影响一轮三通道完整采集的周期，需用真实设备确认。
- 当前/温度换算必须由调用方显式传入 `WordEncoding` 和 `LinearScale`，不会猜测 A/mA 或温度倍率。
- `uhf-gatewayd --v3` 可通过 `--v3-current-multiplier/--v3-current-offset` 及对应温度参数显式提供换算；不提供时只记录下行通信，不发布看似正常的工程值。
- 报警阈值未配置时以 NaN 表示，报警有效位为 0；配置入口和持久化尚未实现，不能把当前默认值当作生产阈值。
- 激活测试使用仓库外临时测试密钥；仓库不包含默认密钥。生产必须通过 `--v3-device-id`、`--v3-activation-key`（或后续制造注入适配层）和可选 `--v3-activation-code` 提供配置，缺任一项时后端拒绝 v3 启动。
- 快照失败时将对应值标为不可用；局放失败通道的原始字不会作为新鲜值发布。具体上行应答选择 NaN、异常码或旧值加质量仍待确认。
