## 正式程序入口与当前边界

当前正式入口仍是 `src/main.cpp` 启动的 `uhf-gatewayd`。使用 `--v3 --v3-pd-device PATH --v3-current-device PATH --v3-temperature-device PATH` 时，它先复核设备绑定激活，再创建三个真实串口、`v3::AcquisitionScheduler`、v3 Modbus/TCP/RTU 分支、候选 IEC 三合一模型、v3 Web 快照和 `data/v3` 历史存储；不传 `--v3` 仍保持旧 PD1000 兼容路径。激活无效时在串口及所有 v3 服务创建前失败，不是只隐藏网页按钮。

下一增量应补三合一参数配置和存储空间/保留期故障测试，再完成最终 IEC 点表/报告互操作、12 点阈值配置和制造激活参数。生产所需电流/温度编码倍率、谱点单位、无效/过期最终约定和 IEC 点表仍需产品输入，代码不得用测试值伪装配置完成。

## 已知暂定策略

- `CollectorOptions::max_retries` 表示首次尝试之外的重试次数，当前默认 3；需求“重试 3 次”尚未明确总尝试次数。
- 局放分段间隔默认 3 秒；PTY 测试把它设为 0。该设置会影响一轮三通道完整采集的周期，需用真实设备确认。
- 当前/温度换算必须由调用方显式传入 `WordEncoding` 和 `LinearScale`，不会猜测 A/mA 或温度倍率。
- `uhf-gatewayd --v3` 可通过 `--v3-current-multiplier/--v3-current-offset` 及对应温度参数显式提供换算；不提供时只记录下行通信，不发布看似正常的工程值。
- 报警阈值未配置时以 NaN 表示，报警有效位为 0；配置入口和持久化尚未实现，不能把当前默认值当作生产阈值。
- 激活测试使用仓库外临时测试密钥；仓库不包含默认密钥。生产必须通过 `--v3-device-id`、`--v3-activation-key`（或后续制造注入适配层）和可选 `--v3-activation-code` 提供配置，缺任一项时后端拒绝 v3 启动。
- 三源时效当前为局放 10 分钟、电流 5 秒、温度 5 秒；基于单调时钟判断，不受系统校时倒退影响。Web 将过期值置 `null`，Modbus 返回异常 04，IEC 保留最后有限值并标 `questionable/oldData`；修改入口是 `v3::FreshnessLimits` 和上行适配器，未标记为用户确认。
- 历史格式当前写 v2（增加三源 UTC 和 stale 位），读取器兼容本轮较早提交产生的 v1；v1 没有源 UTC，读取为未设置而不伪造记录时间。
- 报文查看缓存固定为最多 256 条且载荷总计不超过 64 KiB，只记录三路下行串口实际成功收发的字节块；`read_some` 可能把一个 Modbus 应答分成多个条目。修改上限的入口为 `PacketTraceBuffer` 构造参数；没有报文落盘或导出接口。
- 快照失败时将对应值标为不可用；局放失败通道的原始字不会作为新鲜值发布。上述暂定上行选择仍待最终确认。
