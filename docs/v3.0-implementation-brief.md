# v3.0 实现状态与需求审查

## 0. 结论与边界

当前分支是 `v3.0`。主需求足以开始分模块开发，但不足以在没有协议补充和实机联调的情况下认定整机交付完成。

本轮已经实现并测试**三端口采集、可热配置的采集时序/错误隔离/源时效、统一快照、Modbus/Web API 与正式三合一实时页面、显式串口 profile、工程换算与 12 点报警、候选 IEC 61850 v3 服务模型、v3 历史存储/查询、内存报文查看、后端激活总门禁及显式制造配置后才启动的 v3 systemd/安装链路**。仍不是整机 v3.0：最终 IEC 点表/互操作验收、厂商参数和目标硬件验证尚未完成。没有变更真实目标板、`/data` 服务、frpc、4G 或生产配置。

1. `spec/v3.0/嵌入式开发需求书-综合监测管理机-v3.0.docx`：当前主需求，含第八章对历史笔误的修正。

## 3. 已测试但仍需产品确认的选择

- 电流编码和电流/温度换算倍率必须由配置或主机模拟命令行明确提供；不把未知单位猜成 A、mA 或 0.1℃。配置要求编码/倍率/偏移完整成组且倍率为正有限数，仓库默认使用 `unconfigured`/`null`；未提供时源状态可在线但工程值保持无效。当前转换辅助函数按一组通道同一线性倍率处理；若 CT/传感器倍率逐通道不同，需先补逐通道转换配置。
- 主需求只明确局放和上行 485-4 为 115200/8N1，没有给电流/温度串口参数。两路 profile 默认 `unconfigured`，此时正式进程使用不可用适配器而不是打开 `/dev/ttyS2`/`ttyS3` 猜 115200；保存 profile 后要求重启。当前支持常见 termios 波特率 1200/2400/4800/9600/19200/38400/57600/115200/230400，以及 7/8 数据位、N/E/O 校验、1/2 停止位；其他非标准波特率需目标板适配层。
- 新局放均值/峰值使用 mV；谱图只保留有符号原值，不标成 dBm，也不继承 PD1000 的 `FFBA/FFBC` 特殊值含义。
- 启动不足 50 个有效样本时，调用方必须选择“先报样本不足”或“按已有样本计算”。当前窗口按每相最近 50 个有效采样推进；无效样本跳过，不清空历史。断线/重新配置是否重置，需要进一步确认。
- 除零、溢出、非有限值标成无效；负均值不平衡度的分母提供按原公式、取绝对值、拒绝非正值三种显式策略，没有偷偷选生产默认值。
- 当前 `In/IN/TN` 输出百分数数值，例如 25 表示 25%；`Qa/Qb/Qc` 保持原公式比值，例如 0.25。需要与上位机确认数值语义。
- 电流/温度上行使用 **0x03** 是依据历史方案提出的配置；主需求 §5.1 对该区功能码未像局放 0x04 那样明确写出，发布前需确认。
- 无效 float32 可明确选择规范化 quiet NaN 或 Modbus 异常 04；缺失局放原始字、未知遥信状态和过期测量目前返回异常 04，不伪造正常零值。Web 输出 `null`；IEC 对有最后值的过期数据输出 `questionable/oldData`。这是暂定策略，最终约定仍须与上位机确认。
- 遥信按主需求表格顺序生成 0..14 的线地址，表版本为 1；完整 Modbus 点表由 `point_table_csv()` 从正式常量生成，并通过鉴权 Web 接口/设置页导出。编号可由程序决定，不要求需求方手工编表；配置变化不能偷偷重排地址。最终外部点表版本仍需和上位机共同冻结。
- 每次请求读取线程安全不可变快照；局放、电流、温度各自保留成功/尝试 UTC 时间。当前局放三通道共用该采集源最近一次成功时间；若最终点表要求逐通道独立时间，需要扩展状态结构。

## 4. 待澄清清单（按对联调的影响排序）

1. **电流/温度完整下行定义**（§3.2/3.3、附录 C/D）：两台设备的波特率、校验/停止位；电流 signed/unsigned、A/mA/CT 比例及逐通道倍率；温度 152 究竟表示 152℃ 还是 15.2℃；量程和设备故障码。温度 1/3/5 号寄存器已经明确，不是缺项。
2. **谱点物理含义**（§3.1/8）：单位、倍率、有效范围、无信号/未刷新/传感器故障编码。特征值 mV 不能直接推出谱点也为 mV。
3. **无效和过期数据的最终对外约定**（§5/7）：代码当前把局放 10 分钟、电流/温度 5 秒作为可热配置的暂定默认值，并采用 Web `null`、Modbus 异常 04、IEC `questionable/oldData`，存档记录三源时间/质量。仍需确认生产期限、允许范围、上位机期望以及局放逐通道时间；某个分段失败当前不发布该通道的部分新轮次。
4. **计算边界**（§4）：除数为零怎么办；负温度均值如何定义 TN；百分比线上传 25 还是 0.25；不足 50 次、读取失败、断线恢复、重启/修改周期时如何处理统计窗口。
5. **通信和报警时序**（§3/5.1/7）：局放完整通道间隔、电流/测温周期、超时、重试延时和迟到隔离均已显式配置；当前把“重试 3 次”解释为首次之外额外 3 次，局放 3 秒按相邻两次完整通道读取的开始时刻计算。仍需确认重试总次数语义、连续失败告警/恢复次数、断线退避上限、12 个默认阈值及无效数据时报警保留/复归。回差/防抖无依据时不擅自增加。
6. **IEC 61850 交付点表**（§5.2）：当前代码提供候选 SPDC1..3、MMXU1、STMP1、GGIO1 数据对象、q/t、两个报告数据集，但仍需产品列定最终 DO/DA、单位、报告控制块和客户端验收用例。“MMXU/STMP 类”还不是已验收的互操作接口。相关性、谱图、全部计算值哪些需要上送也应列明。
7. **激活规范和制造配置**（§9）：确定序列号的真实来源、标识拼接格式/主路径、厂家密钥注入与轮换方式；只保存一个“已激活”布尔值不能替代启动时重新核对设备绑定。文中 20 字符、每组 5 个与 `XXXX-XXXX-XXXX-XXXX` 格式矛盾，Base32 字母表、去填充和金样本需固定。普通固件密钥可被提取的风险原文已经承认，不能把它验收为绝对防复制。
8. **目标板与配置边界**（§2/5.4）：确定最终 CPU/发行版、交叉工具链、四个 tty 与网卡名字、RS485 方向控制方式、Wi-Fi/4G 模块及其管理接口。现有构建基准是 AArch64；不能据“ARM/MIPS”推断两个平台都已验证。明确 v3 是否继续保留旧 HTTPS/FTP/事件能力，避免把旧简报要求默认带入。
9. **验收输入和阈值**：补三台设备的脱敏正常/故障报文、实测值对照、上位机读写/报告期望、允许刷新延迟/磁盘内存上限、连续运行时长。主机模拟测试不能替代这些实机验收。

以上多数问题不阻止框架和纯逻辑开发，但不能靠 AI 猜定之后直接声明整机完成。类名、文件拆分、点表生成器、缓存具体容器等普通设计细节，可继续交给实现者决定。

## 5. 本地验证

在仓库根目录：

cmake -S src/v3 -B build/v3 -DCMAKE_BUILD_TYPE=Debug
cmake --build build/v3 --parallel 4
ctest --test-dir build/v3 --output-on-failure

cmake -S src/v3 -B build/v3-release -DCMAKE_BUILD_TYPE=Release

ctest --test-dir build/v3-sanitize --output-on-failure

cmake -S . -B build/host -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Debug -DUHF_ENABLE_IEC61850=ON
cmake --build build/host --parallel 4
ctest --test-dir build/host --output-on-failure

## 6. 后续最小闭环

实时总览已经消费正式 schema 3：可切换三个局放通道，展示七项特征、设备谱点原始值、三源状态/独立时间/运行参数、35 项工程值及质量、12 点报警；WebSocket v3 推送也由正式 PTY 守护进程端到端验证。页面不再含 PD1000、单通道或 dBm 假设。正式发布前还必须完成目标盘压力/真实耗尽测试、最终 IEC 点表/报告互操作、制造激活参数注入、板级串口/RS485 方向控制适配和整机验收。

现有激活门禁覆盖 `--v3` 新运行链路，生产可用 `--v3-device-id-file`、`--v3-activation-key-file` 和首次需要的 `--v3-activation-code-file` 避免把值放入进程参数。读取器拒绝符号链接、非普通文件、非 root/当前用户所有、组可写或其他用户可读写、超长及多行内容。随包 systemd 已要求这些外部文件，安装器不会生成测试默认值；真实设备标识、制造密钥和格式金样本未确认，不能对外提供“已通过生产激活验收”的 v3.0 发布包。
